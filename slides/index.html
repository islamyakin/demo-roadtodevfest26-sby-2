Grafana · the basics

Grafana in six concepts

Data sources

Grafana connects to where data lives and queries it live; it does not store your metrics or logs. Here: 2 Google Cloud data sources.

Explore

Ad-hoc queries over metrics and logs, no dashboard needed. Where an investigation usually starts.

Dashboards & panels

Saved queries drawn as graphs, tables and log lists. Here: “Shop · Overview”, ready at start, plus one you build by prompt.

Alerting

Rules evaluated every minute → firing / resolved, routed to contact points. Here: 5xx ratio and p95 latency.

Plugins & apps

Extend Grafana. Here: the Cloud Logging data source and the Grafana Assistant app.

Provisioning

Data sources and alert rules as YAML in git (provisioning/), loaded at start.

Here

Grafana OSS 13 runs on your laptop in Docker. Nothing to install in Google Cloud.

Grafana Assistant

An AI agent that lives inside Grafana

What it can do

  • Chat in the sidebar, aware of the page you are on
  • Write and explain queries (PromQL, LogQL, SQL…)
  • Run them on your data sources and read the results
  • Create and edit dashboards

How it gets access

It works as your Grafana user: it sees only what your role can see.

Grafana Assistant · how it works

How a question becomes evidence

You ask“Why is frontend failing?”
→
Plansymptom → scope → logs
→
Write queryPromQL / log filter
→
Run iton your data source, as you
→
Read resultnext query, or answer
→
Answerclaim + query + numbers

Loops, not one shot

Runs several queries and refines a query that returns nothing.

Grounded in your data

Answers come from query results, not from what the model remembers.

Still a model

It can pick the wrong label or overreach. Open the query, check it, push back.

Why PromQL

Prometheus is a documented Assistant data source, and Cloud Monitoring speaks PromQL.

Grafana Assistant · RCA playbook

Four questions, evidence for each

1

Scope

Which service, which route, since when? Cloud Run metrics + user_app_* per route

2

Follow the dependency

Failing on its own, or because of backend? same trace id in both services’ logs

3

Resource or code?

CPU and instances vs. what the logs say. “just scale it” is often wrong

4

Root cause + one safe fix

With confidence, evidence and the query behind it. No evidence, no claim.

Prompt that works

“The 5xx alert fires on frontend. Break 5xx down by route, then check whether backend fails for the same traces. Show every query and its result.”

Guardrails

The Assistant reads. You act.

Read-only access

Assistant works as your Grafana user; Google data sources only read.

Least privilege

One service account per service; only frontend-sa may invoke backend.

Humans fix

Every mitigation is a gcloud command a person runs. Terraform can reset it.

Check the query

Models pick wrong labels too. Open the query before you trust the answer.

Data leaves

Prompts and results go to the Assistant backend in Grafana Cloud. Mind your data policy.

Telemetry first

Structured logs + trace ids make AI-assisted RCA possible at all.
